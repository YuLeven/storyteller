## Implemented

- Reviewed campaign setup seeds stable player-owned inventory entries, public world details, GM characters, typed campaign panels, and up to 50 optional player-visible player-character label/value details. Those facts persist with the existing character description and appear in the player projection, board, and GM context; labels/values are bounded and duplicate labels are rejected without adding fixed RPG stats.
- GM proposals can add or revise flexible public facts on the player's character, with a concise action-grounded reason. Validation rejects GM-private player writes, missing reasons, unknown character IDs, and core identity/description changes; accepted patches preserve unrelated facts and apply atomically. The public audit event and timeline show only the fact patch and reason, and updated facts reach the board and later-session GM context. GM-controlled characters keep their existing public/private update behavior.
- GM proposals can introduce a new GM-controlled character mid-play with a stable speaker ID and separate public/private facts. The new character can speak, act, receive items, move, and be updated in the same proposal. Validation rejects duplicate IDs, the reserved player ID, and unknown or invalid places before commit; creation, public/private audit entries, activity, inventory, and presence commit atomically. Public introduction events and projections show only the name, visible facts, and public presence, while both fact scopes and hidden locations remain in later GM context across sessions. This uses the existing character and place tables; no migration is needed.
- The GM receives canonical public and private inventories. Validated add, whole- or partial-stack transfer, consume, and properties-only update operations commit atomically with timeline events; generic state changes cannot edit or replace inventory. Property updates deep-merge nested maps and preserve unrelated values without changing stable IDs or other item fields. Partial splits preserve the source remainder, item properties and visibility, and total quantity. Invalid proposals fail as `invalid_response` and apply no inventory changes.
- Campaign resources now use strict panel transactions: quantity and money fields accept signed deltas applied against their locked canonical values; text, status, and date fields accept typed `set` operations. Every operation requires a reason. Negative results, zero deltas, duplicate fields, malformed operations, and untyped values fail atomically. Visibility-scoped history records field label, unit, before/change/after, and reason; the session timeline renders those details. The GM policy says ledger review alone is not a resource change.
- Campaigns persist campaign-scoped places with stable IDs, descriptions, JSON surroundings, and public or GM-private visibility. The starting world location seeds the player's first place, and a GM character's explicitly visible location seeds known presence.
- Public date, time, and weather aliases collapse to canonical fields at initialization, proposal validation, persistence, projection, and GM-context construction. A legacy conflict resolves from the latest matching public state-change audit event (and uses the existing header precedence when no such event exists); new proposals cannot supply two aliases for the same fact. New patches reconcile legacy state before applying the accepted change, so they cannot be overwritten by older aliases.
- The GM receives both visibility scopes for places and every character's current place. Place creation must precede movement; movement uses a known character and place, and the player cannot move to a GM-private place. Location changes commit with the turn. Generic world changes cannot overwrite the canonical location.
- If one accepted turn records more than one player move, the final destination now drives both the player's canonical place and the public world location; the next session's GM context receives that same location.
- The play board shows the player's current canonical place and surroundings, who is publicly present, tracked campaign resources, owned items, character details, and the campaign story. The location rail follows the player's canonical place even if a legacy world-location string is stale. Flexible item properties are shown as readable, escaped key/value details rather than raw JSON. Public history and projections omit GM-private places and presence.
- Campaign details link directly back to the active session. Starting another session clearly says it will complete the current session while preserving its campaign history.
- The campaign premise is available from the play screen in a collapsed, native disclosure so a player can review the setup story without leaving their session.
- Narrow session layouts have a compact sticky native-link bar for the active turn composer, scene/place, story timeline, and inventory; public objectives and tracked resources get shortcuts only when present. The scene shortcut lands on the current-place card, combining surroundings and who is present; date, time, weather, and location appear once in the compact world header. Fragment targets are focusable, have a visible keyboard focus treatment, and clear the sticky bar when scrolled into view. The navigation is hidden in the existing wide layout.
- On the dark tabletop palette, translucent amber and white card surfaces now keep their intended dark colors; a 370px viewport check confirmed readable campaign commitments, place cards, and nested people/objective rows.
- Shared form labels and helper text using the core Phoenix zinc palette now map to light readable colors on dark pages.
- Stone hover utilities map back to dark tabletop surfaces so light secondary-action labels remain legible during pointer hover.
- Optional setup groups for player facts, starting inventory, GM characters, and campaign panels are labeled, start collapsed when empty, open when populated, and close again when their last row is removed.
- The chronological story timeline stays mounted from the empty state and politely announces newly appended entries to assistive technology without rereading the full list; manual screen-reader review remains on the accessibility QA list.
- The player-facing campaign timeline initially loads at most 500 recent public events. A sequence-based cursor loads earlier pages without gaps or duplicates, preserves already loaded pages across turn refreshes, and uses stable event sequence IDs. Older history stays outside the live region; only the latest 20 entries are politely announced. Session-boundary labels are precomputed in one pass across loaded history.
- Roll-request entries in the public timeline retain the test, difficulty, and target so the terms of a D20 check remain visible after it resolves and across reconnects. Difficulty/target labels reuse Spanish and French translations.
- Public player- and party-owned items have a localized action button that appends a short sentence in the campaign narration language to the editable composer. The server resolves the item ID against the public projection; clicking only changes the draft.
- Campaign history and world state continue across sessions; a new session resumes the same inventory, places, and character positions.
- Optional campaign objectives persist under stable IDs with public or GM-private visibility and open/completed/abandoned status. The GM prompt receives both scopes and must ground completions in established events; ordered create/update operations are validated and committed atomically with audit history. The public board groups visible objectives by status, and private objective titles/details/status stay out of public projections and public audit events.
- Spanish and French catalogs include inventory, location, objective-board, and player-fact audit labels. Campaign-authored content remains in its selected narration language.
- Added an idempotent fictional QA seed, **The Amber Orchard**, with a starting place, NPC presence, flexible orchard stock panels, and a player-owned basket. It is separate from both the existing failed observatory QA turn and the vineyard campaign.
